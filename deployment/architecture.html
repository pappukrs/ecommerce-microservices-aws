The full setup

Follow the numbers. Requests come in on the left, through CloudFront, Cognito and API Gateway, and reach the services privately through the VPC Link and the internal load balancer. Nothing in the VPC is reachable from the internet directly. The services call out through the NAT gateway for everything that lives outside the VPC.

  1. The browser loads the site from CloudFront, which reads the private S3 bucket.
  2. The user signs in with Cognito and receives a JWT.
  3. The site calls API Gateway with the JWT attached.
  4. API Gateway validates the JWT (only GET /products is public), then forwards through the VPC Link to the internal load balancer.
  5. The load balancer routes by path to one of the four Fargate services. order-service calls the other three back through it.
  6. user-service and order-service read and write RDS PostgreSQL.
  7. All services reach AWS APIs through the NAT gateway and internet gateway.
  8. order-service publishes to SNS, which delivers to SQS and email.

Solid line: request traffic. Dashed line: outbound, background or asynchronous traffic.

What a request does

Open the site

  1. The browser asks CloudFront for the page over HTTPS.
  2. CloudFront reads the React build from the private S3 bucket using Origin Access Control.
  3. Product images come from the same bucket, under /images/products/.

Sign in

  1. The React app sends email and password straight to Cognito.
  2. Cognito returns a signed JWT.
  3. The app attaches it to every later API call as Authorization: Bearer ….

Browse products

  1. GET /products reaches API Gateway. This route needs no login.
  2. API Gateway forwards it through the VPC Link to the internal ALB.
  3. The ALB rule /products* sends it to product-service on 8001.
  4. product-service reads the DynamoDB table through the NAT gateway.

Place an order

  1. POST /orders with the JWT. API Gateway checks the token against Cognito first.
  2. The ALB rule /orders* sends it to order-service on 8004.
  3. order-service calls user, cart and product services back through the same ALB.
  4. It writes the order to RDS, then publishes to the SNS topic.
  5. SNS delivers an email and drops a copy in the SQS queue.

These four bill by the hour

The NAT gateway, the load balancer, the RDS instance and the four Fargate tasks cost money for as long as they exist, whether or not anyone uses the site. In module 10, delete them first, then release the Elastic IP. Everything else on the drawing costs close to nothing at this scale.
