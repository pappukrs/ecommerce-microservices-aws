Ecommerce AWS Deployment Guide

Everything needed to build the stack from an empty account and tear it down again, in order. Tick each step as you go; your progress and the values you type are saved in this browser. The picture of what you are building is in architecture.html.

0

Before you start

5 min

Point the terminal and the console at the right account and region, and fill in the worksheet as values appear.

aws --version && docker --version && node --version && npm --version && jq --version

You need AWS CLI v2, Docker, Node.js 20 or newer, and jq. Docker only has to be running from module 5.

Run this in every new terminal. All commands in this guide rely on it.

export AWS_PROFILE=<profile> AWS_DEFAULT_REGION=<region>
aws sts get-caller-identity --query Account --output text

The number printed must be the account you mean to deploy into. Put it in the worksheet.

Top right of the AWS console: choose Asia Pacific (Mumbai). Check it again whenever you open a new service; a resource created in the wrong region will not show up anywhere else.

Worksheet

Type values here as you create things. They are filled into the commands below and stay in this browser only.

Cost. Four things bill by the hour from the moment they exist: the NAT gateway (module 1), the RDS instance (module 4), the load balancer and the four Fargate tasks (module 5). Together they come to roughly $4 a day. Finish in one or two sittings and run the cleanup at the end.

Networking

15–20 minVPC consoleNAT gateway bills hourly

One VPC across two Availability Zones with public, private ECS and private database subnets, an internet gateway, a NAT gateway and three route tables.

VPC → Your VPCs → Create VPC → “VPC only”

  • Name: ecommerce-vpc
  • IPv4 CIDR: 10.10.0.0/16, no IPv6, default tenancy

VPC → Internet gateways → Create

  • Name: ecommerce-igw
  • Then Actions → Attach to VPC → ecommerce-vpc

VPC → Subnets → Create subnet → VPC ecommerce-vpc

NameCIDRZone
ecommerce-public-subnet-110.10.0.0/24ap-south-1a
ecommerce-public-subnet-210.10.1.0/24ap-south-1b
ecommerce-private-ecs-110.10.10.0/24ap-south-1a
ecommerce-private-ecs-210.10.11.0/24ap-south-1b
ecommerce-private-database-110.10.20.0/24ap-south-1a
ecommerce-private-database-210.10.21.0/24ap-south-1b

You can add all six in one “Create subnet” form with “Add new subnet”.

VPC → NAT gateways → Create

  • Name: ecommerce-nat-gateway
  • Subnet: ecommerce-public-subnet-1, connectivity type Public
  • Click Allocate Elastic IP
  • Wait until the state is Available before the next step

VPC → Route tables → Create → VPC ecommerce-vpc

NameAdd routeAssociate subnets
ecommerce-public-rt0.0.0.0/0 → Internet gatewayBoth public
ecommerce-private-ecs-rt0.0.0.0/0 → NAT gatewayBoth private ECS
ecommerce-private-db-rtNoneBoth private database
Watch out. The ECS route table must point at the NAT gateway, not the internet gateway. With the internet gateway the tasks get no outbound access (they have no public IP) and fail to pull images in module 5.
VPC=$(aws ec2 describe-vpcs --filters Name=tag:Name,Values=ecommerce-vpc --query 'Vpcs[0].VpcId' --output text)
aws ec2 describe-subnets --filters Name=vpc-id,Values=$VPC \
  --query 'sort_by(Subnets,&CidrBlock)[].[Tags[?Key==`Name`]|[0].Value,CidrBlock,AvailabilityZone]' --output table
aws ec2 describe-nat-gateways --filter Name=vpc-id,Values=$VPC --query 'NatGateways[].[NatGatewayId,State]' --output table
aws ec2 describe-route-tables --filters Name=vpc-id,Values=$VPC \
  --query 'RouteTables[].{Name:Tags[?Key==`Name`]|[0].Value,Default:Routes[?DestinationCidrBlock==`0.0.0.0/0`]|[0].[GatewayId,NatGatewayId],Subnets:length(Associations[?SubnetId!=null])}' --output json
Expect. Six subnets, NAT gateway available, the public table’s default route showing an igw-…, the ECS table’s showing a nat-…, the database table’s empty, and two subnets on each of the three named tables. A fourth table with no name and no subnets is the VPC’s main route table; leave it alone.

Authentication with Cognito

5–10 minCognito console

A user pool for accounts and an app client the React app signs in through.

Cognito → User pools → Create user pool

  • Application type: Single-page application (SPA)
  • Application name: ecommerce-app
  • Sign-in identifier: Email
  • Self-registration: enabled
  • Required attributes: email and name
  • Return URL: leave blank

The wizard gives the pool an automatic name such as “User pool - abc123”. Only the app client is called ecommerce-app. That is fine.

The user pool → App clients → ecommerce-app → Edit

  • ALLOW_USER_PASSWORD_AUTH
  • ALLOW_USER_SRP_AUTH
  • ALLOW_REFRESH_TOKEN_AUTH

Copy the User pool ID and App client ID into the worksheet.

aws cognito-idp describe-user-pool-client --user-pool-id <user-pool-id> --client-id <client-id> \
  --query 'UserPoolClient.{Name:ClientName,Secret:ClientSecret,Flows:ExplicitAuthFlows}' --output json
Expect. The three flows listed and Secret null.

Frontend hosting

20 minS3, CloudFront, terminal

A private S3 bucket holding the React build, served over HTTPS by CloudFront. Login works at the end; products appear after module 7.

S3 → Create bucket → General purpose

  • Name: ecommerce-frontend- plus your account ID (it must be globally unique)
  • Keep Block all public access on, versioning off, default encryption

The console may add a suffix to the name. Copy the exact final name into the worksheet.

CloudFront → Distributions → Create distribution

  • Name: ecommerce-distribution, type Single website or app
  • Origin type: Amazon S3, and select the bucket
  • Keep “Allow private S3 bucket access to CloudFront” and the recommended cache settings
  • Security: Do not enable security protections (the other option adds a paid WAF)

Copy the distribution domain name and ID into the worksheet.

The distribution → General → Edit, then the Error pages tab

  • Default root object: index.html, then Save
  • Error pages → Create custom error response: code 403, customize = Yes, path /index.html, response code 200
  • Repeat for code 404

These make React’s client-side routes such as /orders load when opened directly.

From the repo root. Leave the API URL empty for now.

cd frontend/react-app
cat > .env <<'EOF'
REACT_APP_USER_POOL_ID=<user-pool-id>
REACT_APP_USER_POOL_CLIENT_ID=<client-id>
REACT_APP_API_BASE_URL=
EOF
npm install
npm install --no-save typescript@4.9.5
npm run build
aws s3 sync build/ s3://<frontend-bucket> --delete --exclude "images/*"
cd ../..
Watch out. Without the TypeScript line the build fails with Environment key "jest/globals" is unknown: npm installs TypeScript 7, which react-scripts 5 cannot load. Repeat that line after any fresh npm install.

Cognito → the user pool → App clients → ecommerce-app → Login pages → Edit

Set both Allowed callback URLs and Allowed sign-out URLs to:

https://<cloudfront-domain>
Watch out. “Callback URL contains invalid characters” means a space before or after the URL. Clear the field and paste again.
aws cloudfront get-distribution --id <distribution-id> \
  --query 'Distribution.{Status:Status,Root:DistributionConfig.DefaultRootObject,Errors:DistributionConfig.CustomErrorResponses.Items[].[ErrorCode,ResponsePagePath,ResponseCode]}' --output json
curl -s -o /dev/null -w "/ %{http_code}\n" https://<cloudfront-domain>/
curl -s -o /dev/null -w "/orders %{http_code}\n" https://<cloudfront-domain>/orders
Expect. Status Deployed, root index.html, both error codes mapped, and 200 for both URLs. Then open the site, sign up, confirm the emailed code and log in. The product list is empty until module 7.

  • ecommerce/product-service
  • ecommerce/cart-service
  • ecommerce/user-service
  • ecommerce/order-service

Leave tag mutability on Mutable and encryption on AES-256.

From the repo root:

sudo systemctl start docker
REG=<account-id>.dkr.ecr.<region>.amazonaws.com
aws ecr get-login-password | docker login --username AWS --password-stdin $REG

for SVC in product-service cart-service user-service order-service; do
  docker build -t ecommerce/$SVC services/$SVC
  docker tag ecommerce/$SVC:latest $REG/ecommerce/$SVC:latest
  docker push $REG/ecommerce/$SVC:latest
done

On an Intel or AMD machine the images are amd64, which matches Linux/X86_64 in the task definitions. On an ARM machine choose Linux/ARM64 there instead.

IAM → Roles → Create role → AWS service → Elastic Container Service

  • Use case: Elastic Container Service Task (“Allows ECS tasks to call AWS services on your behalf”)
  • Attach: AmazonDynamoDBFullAccess_v2, AmazonSSMReadOnlyAccess, CloudWatchLogsFullAccess, AmazonS3ReadOnlyAccess, AmazonSNSFullAccess
  • Role name: ecommerce-ecs-task-role
Watch out. Two traps on the permissions page. Picking the plain “Elastic Container Service” use case locks the role to one fixed policy. And the list at the bottom is for a permissions boundary: leave it on “Create role without a permissions boundary”, or the role is capped to whatever you tick there. The review page must show five permissions policies and no boundary line.

Give the tasks two to three minutes to start.

aws ecs describe-services --cluster ecommerce-cluster \
  --services ecommerce-product-service ecommerce-cart-service ecommerce-user-service ecommerce-order-service \

Order notifications

15 minSNS, SQS, Parameter Store, ECS

Each new order is published to an SNS topic, which delivers it to an email address and to an SQS queue.

SNS → Topics → Create topic

  • Type: Standard (the form defaults to FIFO)
  • Name: ecommerce-order-events, display name eCommerce Order Events

SQS → Create queue

  • Type: Standard, name ecommerce-order-shipping
  • On the queue page: Subscribe to Amazon SNS topic → ecommerce-order-events

Subscribing from the SQS side also adds the queue policy that lets SNS deliver to it.

SNS → the topic → Create subscription

  • Protocol: Email, endpoint: your address
  • Open the email from AWS and click Confirm subscription

Systems Manager → Parameter Store → Create parameter (String)

Name /ecommerce/dev/sns/topic-arn, value:

arn:aws:sns:<region>:<account-id>:ecommerce-order-events

It reads parameters only at startup.

aws ecs update-service --cluster ecommerce-cluster --service ecommerce-order-service --force-new-deployment --query 'service.serviceName'
aws ecs wait services-stable --cluster ecommerce-cluster --services ecommerce-order-service && echo ready

Or in the console: the cluster → tick the service → Update → Force new deployment.

aws sns list-subscriptions-by-topic --topic-arn arn:aws:sns:<region>:<account-id>:ecommerce-order-events \
  --query 'Subscriptions[].[Protocol,SubscriptionArn]' --output table
Q=$(aws sqs get-queue-url --queue-name ecommerce-order-shipping --query QueueUrl --output text)
aws sqs get-queue-attributes --queue-url $Q --attribute-names ApproximateNumberOfMessages --query Attributes
Expect. Two confirmed subscriptions (no “PendingConfirmation”), an email within a minute of placing an order, and the queue’s message count going up by one.

Cleanup

20–30 minAll consoles

Delete everything in reverse order. The hourly-billed resources go early; the VPC goes last because everything else lives in it. (Module 9, custom domain, is optional and not part of this run.)

  • SNS → Subscriptions → delete both
  • SNS → Topics → delete ecommerce-order-events
  • SQS → delete ecommerce-order-shipping
  • API Gateway → APIs → delete ecommerce-api
  • API Gateway → VPC links → delete ecommerce-vpc-link

The VPC link takes a few minutes to release its network interfaces. The VPC cannot be deleted until it has.

  • ECS → ecommerce-cluster → Services → delete all four (tick “Force delete”)
  • When no tasks remain: delete the cluster
  • Task definitions → each family → select all revisions → Deregister

Or from the terminal:

for S in product cart user order; do
  aws ecs delete-service --cluster ecommerce-cluster --service ecommerce-$S-service --force --query 'service.status' --output text
done
aws ecs wait services-inactive --cluster ecommerce-cluster \
  --services ecommerce-product-service ecommerce-cart-service ecommerce-user-service ecommerce-order-service
aws ecs delete-cluster --cluster ecommerce-cluster --query 'cluster.status' --output text
  • EC2 → Load balancers → delete ecommerce-internal-alb
  • EC2 → Target groups → delete all four (after the load balancer is gone)

ECR → select the four ecommerce/… repositories → Delete. This removes the images too.

  • RDS → Databases → ecommercedb-instance → Actions → Delete
  • Untick “Create final snapshot” and “Retain automated backups”, tick the acknowledgement
  • After it is gone (several minutes): Subnet groups → delete ecommerce-db-subnet-group
  • DynamoDB → Tables → delete ecommerce-products and ecommerce-cart
  • Parameter Store → delete all seven /ecommerce/dev/… parameters
  • CloudFront → the distribution → Disable, wait until it finishes deploying, then Delete
  • S3 → the frontend bucket → Empty, then Delete
  • CloudFront → Origin access → delete the leftover origin access control

Cognito → the user pool → Delete. If it refuses, first delete its domain under Branding → Domain and turn off deletion protection in the pool settings.

  • IAM → Roles → delete ecommerce-ecs-task-role and ecsTaskExecutionRole
  • CloudWatch → Log groups → delete the four /ecs/ecommerce-… groups

Leave AWSServiceRoleForECS; it is managed by AWS and costs nothing.

  • VPC → NAT gateways → delete ecommerce-nat-gateway, wait for state Deleted
  • VPC → Elastic IPs → select the address → Release
Watch out. An Elastic IP that is not attached to anything still bills by the hour. Release it.

VPC → Your VPCs → ecommerce-vpc → Actions → Delete VPC. This also removes its subnets, route tables, internet gateway and security groups. If it reports a dependency, something above is still deleting; wait a few minutes and try again.

echo "NAT:      $(aws ec2 describe-nat-gateways --filter Name=state,Values=available,pending --query 'length(NatGateways)')"
echo "EIPs:     $(aws ec2 describe-addresses --query 'length(Addresses)')"
echo "RDS:      $(aws rds describe-db-instances --query 'length(DBInstances)')"
echo "ALBs:     $(aws elbv2 describe-load-balancers --query 'length(LoadBalancers)')"
echo "Clusters: $(aws ecs list-clusters --query 'length(clusterArns)')"
echo "VPCs:     $(aws ec2 describe-vpcs --filters Name=tag:Name,Values=ecommerce-vpc --query 'length(Vpcs)')"
